Screen reader scrolling tests

These pages support issue 4: Evaluate utility of declarative scroll buttons for screen reader users.

Purpose

Content in a scroll container is always in the accessibility tree, so screen reader users can read all of it without scrolling. Screen reader users who also look at the screen benefit when the visible area follows the reading cursor. If screen readers already scroll content into view as the reading cursor moves, scroll buttons add little for those users.

These tests check whether moving the reading cursor (and, in one test, focus) changes the scroll position of a scroll container, and whether that scrolling respects scroll snapping. None of the pages have scroll buttons; each has an ordinary scroll container with a normal scroll bar.

Tests

  1. Test 1: Vertical scrolling, no snapping
  2. Test 2: Vertical scrolling, mandatory snapping, one card per page
  3. Test 3: Horizontal scrolling, no snapping
  4. Test 4: Horizontal scrolling, mandatory snapping on every card
  5. Test 5: Horizontal scrolling, mandatory snapping, pages of two cards
  6. Test 6: Horizontal scrolling, proximity snapping
  7. Test 7: Horizontal scrolling, pages of two cards, with a link in each card

Screen reader and browser combinations

  • VoiceOver on macOS with Chrome and with Safari
  • JAWS with Chrome and with Firefox
  • NVDA with Chrome and with Firefox
  • Narrator with Edge
  • VoiceOver on iOS with Safari
  • TalkBack with Chrome

For VoiceOver on macOS, note whether cursor tracking is on or off (Control+Option+Shift+F3 toggles it).

Reading the results

Each test page has a scroll log after the scroll container. The page adds an entry when the container stops scrolling, saying which cards are fully or partly visible, and when focus moves inside the container. It is not a live region, so it does not interrupt the screen reader. Read it, or use the Copy log button, after moving through the cards. The copied log includes the browser's user agent string.

Note that a page cannot see where a screen reader's reading cursor is. The log records only what the browser scrolled and where focus went. The cards show large numbers so that screenshots also show which cards are visible.

Reporting

Post results as a comment on issue 4. For each run, include:

  • Screen reader and version, browser and version, and operating system
  • Relevant settings, such as VoiceOver cursor tracking or verbosity
  • The test number and the navigation method used
  • What happened, and the copied scroll log
